# 海斗决策库

> 海克斯大乱斗的英雄强度、海克斯选择与情境出装查询工具。

在线访问：[海斗决策库](https://tsuiho6.github.io/aram-mayhem-guide/)

海克斯大乱斗里，真正难查的不是英雄技能，而是这一局应该如何根据「我玩的英雄、拿到的海克斯、对面的威胁」做决定。

海斗决策库把这些信息整理成一个方便临场查询的静态网站，重点回答：

- 这个英雄当前强不强，核心海克斯是什么？
- 看到某个海克斯，哪些英雄最适合拿？
- 拿到海克斯后，具体先买什么、下一件买什么？
- 对面有多爆发、多控制或多前排时，出装顺序要不要改变？
- 没有拿到关键联动海克斯时，应该回到哪条备用路线？

## 网站内容

### 英雄强度排行

按版本快照查看英雄强度、统计胜率、样本量、核心海克斯和常见构筑方向。支持按战士、法师、射手、前排、刺客、辅助等定位筛选，也可以搜索英雄、海克斯或装备关键词。

英雄详情会展示：

- 当前强度等级与统计状态
- 核心海克斯
- 阶段化出装顺序
- 海克斯联动出装
- 面对不同敌方威胁时的调整建议
- 统计数据与编辑规则的来源边界

### 海克斯推荐榜

海克斯榜按白银、黄金、棱彩分开查看，不把不同稀有度混在同一张表里。点击海克斯后，可以继续查看：

- 最适配的三个英雄
- 这些英雄拿到海克斯后应该出的装备
- 已整理的联动海克斯
- 不适合直接照搬的阵容、英雄或对局条件
- 是否有真实统计样本或仅有编辑攻略

### 情境出装决策

这是网站的核心查询入口。选择：

1. 我的英雄
2. 我拿到的海克斯
3. 对面威胁
4. 已经购买的装备（可选）

页面会直接给出：

- 现在应该买什么
- 下一件买什么
- 后续第三件和后期替换方向
- 哪些装备不建议优先购买
- 没有关键联动海克斯时的备用路线
- 每件装备的作用和推荐原因

装备路线会明确拆成：

`起手装备 → 第一件核心装 → 鞋子 → 第二件装备 → 第三件装备 → 后期替换装备`

## 数据与实现

这是一个纯静态、前端优先的查询原型，适合部署在 GitHub Pages，不需要后端服务器或大模型 API。

当前仓库包含：

- 26.19 版本的 173 位英雄目录
- 211 个海克斯条目
- 白银、黄金、棱彩海克斯分类
- 英雄强度与海克斯统计快照
- 公开组合攻略整理出的海克斯联动出装
- 对面多爆发、多控制、远程消耗、多前排等威胁规则
- 15 条核心英雄阶段出装覆盖
- 英雄头像与装备图标
- 国服简体中文英雄名和装备名映射
- JSDoc 数据结构约束与自动校验脚本

主要数据文件：

| 文件 | 用途 |
| --- | --- |
| `data/aram-mayhem-26.19.json` | 英雄、海克斯与统计快照 |
| `data/augment-build-guides.json` | 海克斯联动出装攻略 |
| `data/decision-rules.json` | 对面威胁与出装决策规则 |
| `data/build-order-overrides.json` | 英雄阶段化出装覆盖 |
| `data/zh-cn-localization.json` | 海克斯简体中文名称 |
| `data/zh-cn-item-names.json` | 国服装备正式名称 |
| `types.js` | Hero、Augment、BuildRoute 等 JSDoc 类型 |
| `scripts/validate-data.mjs` | 数据结构与完整性校验 |

页面数据与展示逻辑分离，后续可以替换统计快照而不需要重写界面。

## 数据口径

项目会明确区分「统计结果」和「编辑推荐」：

- 英雄胜率、样本量和部分英雄专属海克斯来自公开聚合数据。
- 海克斯联动和情境出装来自公开玩法资料整理与编辑规则。
- 情境规则不是分层联合胜率，也不代表每一局都必须照搬。
- 样本量不足的内容不会被包装成确定结论。
- 当前快照为 26.19，使用前应注意游戏版本更新可能带来的数值和装备变化。
- 数据来源不代表 Riot Games 官方统计，本项目也不隶属于 Riot Games。

## 本地运行

项目不依赖构建工具，直接使用静态文件服务器即可预览。

例如在仓库目录运行：

```bash
python -m http.server 8080
```

然后打开 <http://localhost:8080/>。

提交前可以运行数据校验：

```bash
node scripts/validate-data.mjs
node --check app.js
```

## GitHub Pages 部署

仓库通过 GitHub Actions 部署静态站点：

1. 将仓库推送到 `main` 分支。
2. `.github/workflows/pages.yml` 自动发布站点。
3. 在仓库的 Pages 设置中选择 GitHub Actions 作为构建来源。
