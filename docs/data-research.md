# 海克斯大乱斗数据研究结论

更新时间：2026-09-26

## 结论摘要

目前已经存在多个海克斯大乱斗数据站，也存在可参考的开源采集器和网站项目。第一阶段不应重复造一个单人战绩采集器，而应采用：

1. 现有公开数据作为版本信号和交叉校验。
2. `ARAM-Mayhem-Database` 的脱敏社区贡献模式作为公共数据集参考。
3. 人工整理的英雄玩法作为产品差异化内容。
4. 本地采集器作为后续扩大数据量的贡献工具，而不是网站唯一数据来源。

## 现有数据站

| 来源 | 可观察内容 | 使用方式 | 风险/限制 |
| --- | --- | --- | --- |
| 乱斗网 | 英雄、海克斯、装备、技能、版本趋势 | 研究信息架构和统计字段 | 需确认数据授权与上游口径 |
| ARAMKit | 英雄、海克斯、装备、技能、平衡参数、分段 | 研究功能覆盖和筛选方式 | 首页数据口径不够透明 |
| Hexdata | 英雄、海克斯、出装、阵容 | 作为规模与字段参考 | 公开页面声明样本不代表全量 |
| ARAMGG | 英雄、海克斯、出装、攻略 | 参考英文玩法和版本文章 | 数据来源与 Riot API 的关系需单独核实 |
| ARAM Mayhem | 英雄榜、海克斯榜、出装和攻略 | 参考内容组织方式 | 不同站点可能不是同一数据源 |

几个站点出现相同或接近的英雄、海克斯和场次规模时，不能把它们当作独立样本相加。应将其视为候选来源，记录来源、版本、更新时间和统计口径后再交叉比较。

## GitHub 参考项目

### ARAM-Mayhem-Database

最接近本项目的数据基础设施参考：

- LCU 本地收集 Mayhem 对局。
- 通过种子玩家扩展可观测的对局范围。
- 使用 SQLite 保存私有原始数据。
- 导出不含 PUUID、Riot ID 和爬虫状态的分享文件。
- 通过 GitHub Issue 接收数据贡献。
- 公开侧只发布去身份化聚合结果。
- 统计侧区分 patch、queue、region、时间范围和数据来源。

项目地址：<https://github.com/Lanternko/ARAM-Mayhem-Database>

### aramgg_client

适合参考 Windows 客户端工具：

- LCU 游戏阶段识别。
- 屏幕区域 OCR 识别海克斯。
- 本地数据缓存和版本更新。
- 选人阶段与对局中的展示逻辑。

项目地址：<https://github.com/valkia/aramgg_client>

### mayhem-tracker

适合参考个人战绩同步、SQLite 存储、历史导入和战绩导出：

项目地址：<https://github.com/Yhprum/mayhem-tracker>

### league-aram-builder / mayhem-overlay

适合参考海克斯评分、敌方阵容感知、出装路径和 OCR 联动，但不要直接把它们的推荐结果当成事实数据。

项目地址：

- <https://github.com/fabs133/league-aram-builder>
- <https://github.com/zp96-cmd/mayhem-overlay>

## 本项目的数据分层

### A. 静态游戏数据

英雄、装备、技能、图标、模式数据和版本信息。

建议来源：Riot Data Dragon、CommunityDragon。每次保存时记录具体版本和抓取时间。

### B. 统计快照

英雄、海克斯、装备和组合的聚合观察值。

最低字段：

```text
source
queue
patch
region
observedAt
timeRange
sampleCount
metricDefinition
```

### C. 玩法知识

英雄的核心机制、海克斯联动、出装逻辑、适用场景、反例和操作重点。

这部分必须与统计结果分开保存，因为“历史上经常出现”不等于“每局都应该照抄”。

### D. 社区贡献

接收经过脱敏和结构校验的对局快照。原始数据不直接公开，公开侧只生成聚合结果。

## 统计质量规则

- 不混合普通 ARAM 和 ARAM: Mayhem。
- 不跨 patch 直接合并为一个当前版本结论。
- 低样本内容不得直接按原始胜率排序。
- 组合数据应同时显示样本量和时间范围。
- 统计关联不能写成因果结论。
- 训练或评估数据使用时间切分，避免版本信息泄漏。
- 同一来源的多个页面不能重复计数。
- 每条公开结论都保留来源和生成快照。

## 当前开发顺序

1. 完成英雄玩法库的页面信息结构。
2. 为英雄、海克斯、玩法和装备建立稳定 JSON schema。
3. 加入版本与来源登记页面。
4. 选择一个可验证的数据快照做导入适配器。
5. 研究脱敏数据贡献流程，不把公开站点的隐藏接口写死为依赖。
6. 再做 Windows 采集器和贡献文件导出。
